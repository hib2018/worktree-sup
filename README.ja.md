# worktree-sup

[English](README.md) | 日本語

`wsup`は、fxを利用するGit worktree管理CLIです。Goで実装し、作成・一覧・通常マージ・承認付き競合解消・安全な削除を支援します。

## ビルド

Go 1.23以降、Git（`worktree list --porcelain -z`対応版）が必要です。

```sh
go build -o wsup ./cmd/wsup
# または
go install ./cmd/wsup
```

fx連携は現在 **macOS + native Mach-O版fx + `/usr/bin/sandbox-exec`** のみ対応します。LinuxではLLMが必要な処理を停止し、隔離なしの実行には切り替えません。シェルラッパー版fxも拒否します。`fx`はPATHから検索します。

保存済みのfxモデル・プロバイダ設定とログイン状態（Codexサブスクリプションを含む）を利用します。`fx status`で状態を確認し、必要なら`fx login`で認証してください。サンドボックスから共有するのは`~/.fx`の特定ファイルだけです。設定は読み取り専用とし、プロバイダ認証ファイル・排他用ロック・限定した認証更新用一時ファイルのみ更新を許可します。設定の検出に必要なHOMEと`.fx`のディレクトリのオープン・一覧取得は許可しますが、配下の任意ファイルは読めません。fxが`.fx`ディレクトリ自体のアクセス権を非公開に設定することも許可しますが、ディレクトリ配下への任意の書き込みは許可しません。別ファイルのMCP設定やskillsは共有しません。作業ディレクトリ・XDGディレクトリ・一時ファイルは引き続き隔離します。環境変数のAPIキーも利用でき、引き継ぐのは`AI_GATEWAY_API_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`のみです。認証失敗や不正な出力の場合は停止し、隔離なしの実行には切り替えません。

## 使い方

Gitリポジトリ内で実行します。対話入力は改行で確定します。確認は`[y/N]`で表示し、`y`で承認、`N`で拒否します。空入力も拒否となり、`y`を明示した場合のみ承認します。

入力・一覧選択・確認待ちでは、**Ctrl+C**または**Esc**でEnterなしにキャンセルできます。矢印キーではキャンセルしません。Ctrl+Cはモデル呼び出しや設定済みテストの実行中も中断します。キャンセル時は終了コード130となり、変更済みの内容や進行中のマージを自動で巻き戻さず保持します。`wsup status`で状態を確認し、必要に応じて`wsup resume`または`wsup abort`を実行してください。

```sh
wsup new --base main 'ログイン画面の入力検証を改善する'
wsup list
wsup merge
wsup merge --target release
wsup remove
```

- `new`: 作業内容と起点を指定（省略時は質問）。fxが短いブランチ名と日本語の要約を生成します。名前の安全性・重複・保存先を検証し、起点／名前／要約／パスを表示して作成します。既存の変更は移動・コピーしません。
- 保存先は最初のworktreeのパスに`.worktrees`を付けた隣接ディレクトリです。ブランチ名中の`/`は保存先では`-`に変換し、衝突時は停止します。
- `list`: fxを呼ばず読み取り専用で表示します。端末の画面幅に合わせて列幅を調整し、長い値は`…`で省略します。パイプやファイルへの出力では値を省略しません。見出しと値の間だけに横線を置き、端末では見出しのみ太字にします（リダイレクト時、`NO_COLOR`指定時、`TERM=dumb`では装飾なし）。`PATH`はmainリポジトリ（最初のworktree）のルートからの相対パスで、main自身は`.`です。別worktree内から実行しても基準は変わりません。外部で作成されたworktreeは`unregistered`（未登録）と表示します。
- `merge`: 管理対象の一覧から、空白区切りの番号（例: `1 3`）で入力順に、または`all`で一覧順に選択します。従来どおり番号1つでも選択できます。`--target`は選択した全件に適用し、省略時は各項目に記録された統合先（初期値は作成時の起点）を使います。統合先の変更は記録します。マージは順番に実行し、毎回その統合先の最新状態に取り込みます。統合先は別worktreeにcheckout済みである必要があります。自動checkoutはしません。
- `remove`: 選択画面で番号1つ、空白区切りの番号（例: `1 3`）で入力順に、または`all`で一覧順に選択します。各項目のパス・ブランチ・統合状態を表示し、毎回明示的な承認を得てworktreeとローカルブランチを削除します。クリーンかつ記録された統合先に祖先として取り込み済みの場合のみ削除します。ignoredファイルも残っていれば停止します。現在のディレクトリを含むworktreeは削除できません。失敗・承認拒否・キャンセル時は一括処理を停止して残りの項目を表示し、削除済みの項目は保持します。`resume`と`abort`は現在の操作だけが対象で、残りのキューは保存しません。対処後に`wsup remove`を再実行してください。`all`は選択画面への入力で、コマンド引数ではありません。

一括マージは競合が未完了の間、次の項目へ進みません。fxが解消案を生成し、後述の既存の適用承認・完了確認を求めます。競合したマージが正常に完了した後も、次の選択項目へ進むには明示的な`y`が必要です。失敗・承認拒否・キャンセル時は一括処理を停止して残りの項目を表示し、完了済みのマージは保持します。`wsup resume`と`wsup abort`は現在の操作だけが対象です。残りのキューは保存しないため、現在の操作に対処した後、`wsup merge`を再実行して残りを処理してください。

未コミット変更・未追跡ファイル・進行中のGit操作がある対象ではマージ／削除を止めます。取り込み元のパスと衝突するignoredファイルも上書きしません。通常のマージが競合マーカーを生成することは実行前に表示します。

## Issueからのworktree作成

`wsup issue [--base BRANCH]`は、GitHubのopen issueごとにworktreeを作成します。`gh api --paginate --slurp`に対応した`gh`のインストールと認証が必要です。worktreeを作成する前にopen issueの全ページを取得し、プルリクエストを除外します。対象が0件なら、何も変更せず終了コード0で終了します。

名前の生成にfxは呼びません。issue番号Nにはブランチ`issue-N`を使い、元のissueタイトルをそのまま要約にし、issue番号とURLをメタデータに保存します。`--base`を省略すると起点ブランチを一度だけ質問し、バッチ全体で使います。

issue番号とURLが一致し、既存のwsup管理対象のissue worktreeであると検証できたものだけをスキップします。それ以外のブランチ・パス・メタデータの衝突は、スキップや上書きをせず停止します。

issueは順番に処理します。失敗やキャンセル時は処理を停止し、作成済みworktreeを保持します。`Created`（作成済み）、`Skipped`（スキップ済み）、`Unprocessed`（未処理）の結果を表示し、必要に応じて現在のissueが未完了の可能性も示します。`wsup resume`と`wsup abort`は`new`と同じ復旧規則に従い、バッチ全体ではなく現在のissueだけを対象にします。そのissueへの対処後、`wsup issue`を再実行して残りを処理してください。

## 競合解消とテスト

競合時は、ベース・双方の内容・現在の競合ファイルをfxに送り、変更意図・方針・具体的な差分を表示します。承認前に解消編集・ステージング・コミットは行いません。承認はその差分と状態にのみ有効です。HEAD・インデックス・ファイルが変わっていれば適用しません。

初版の自動解消はUTF-8の通常ファイルを対象とします。バイナリ、symlink、submodule、削除を伴う競合、モード変更などは安全側に停止します。送信する競合コンテキストと差分の上限は各2 MiBです。秘密情報を含むファイルの送信には注意してください。

リポジトリ単位のテストを明示設定できます。コマンドは引数配列として実行し、暗黙のシェル解釈は行いません。

```sh
wsup config test -- go test ./...
wsup config test --clear
```

競合解消後は、未解消競合がないことを確認し、完了確認を得てテストを実行します。失敗時はマージコミットを作りません。テストが対象の追跡ファイル／インデックス等を変更した場合も停止します。追加の修正を古い承認で自動適用することはありません。テスト未設定時は未検証と表示し、続行確認を求めます。

競合のない通常マージは追加承認・テスト実行なしで完了します。自動rebase・squash・push・commit/stashによる既存変更の整理・強制削除・マージ後の自動削除は行いません。

## 中断・再開

共有Gitディレクトリの`wsup/`に要約・起点・統合先・設定・処理段階・提案差分を保存します。worktree間で共有され、Gitの追跡対象にはなりません。変更操作は共有ディレクトリの`wsup.lock`をOSロックして直列化します。プロセス終了時にはロックが解放されます。

```sh
wsup status
wsup resume
wsup abort
```

- `resume`は現在の状態を確認してから再開します。未適用の競合解消案は再生成し、新しい承認を必要とします。適用済みなら保存時の状態との一致を確認し、テスト／完了について再確認します。
- `abort`は明示確認を得て操作記録を中止します。作成済みworktreeや部分的に削除済みの資源は自動復元・削除しません。
- 進行中のマージの中止は、保存した状態と一致する場合のみ`git merge --abort`を実行します。中断後に手作業で変更した場合は自動復旧せず停止します。状態を確認し、必要なら対象worktree内で手動で`git merge --abort`してください。
- Git実行と状態保存は単一トランザクションではありません。再開時に安全性を確認できない状態（ブランチだけ作成された場合など）は停止し、手動確認を必要とします。

手動Gitや外部エージェントはwsupのロックに従いません。操作直前の再検証とref削除時の比較で変更を検出しますが、外部操作との完全な原子性は保証しません。同じworktreeへの同時編集は避けてください。

## fxの隔離境界

fxにはGitリポジトリを直接読ませず、必要なテキストだけ標準入力から渡します。実行環境側でリポジトリの読み書き、fork、shellやGitなどの別プログラムの起動を禁止します。一時領域以外への書き込みは、特定のfx認証・ロックファイルと、その直下に置く認証更新用一時ファイル（`.tmp.*`または`{auth,chatgpt-auth,grok-auth}.json.tmp.*`）に限定します。入れ子のパスや設定ファイルの置き換えは許可しません。Gitの変更はCLIが検証した引数／承認済み差分で実行し、Git hooksと署名の自動起動も無効にします。

TLS検証のためmacOSのシステム証明書ストア（`/Library/Keychains/System.keychain`）の読み取りを許可します。ユーザーのキーチェーンへのアクセスは許可しません。ネットワークはモデル接続のため許可されます。これは完全なネットワーク隔離ではなく、送信した内容・APIキーの外部送信やネットワーク経由の副作用を防ぐものではありません。インストール済みfx・保存済みfx設定・モデル提供元・明示設定するテストコマンド・Git設定は信頼する前提です。

## 開発・検証

```sh
go test ./...
go test -race ./...
go vet ./...
# インストール済みfxを隔離してhelp/versionだけ検証（モデル呼び出しなし）
WSUP_FX_SMOKE=1 go test ./internal/wsup -run '^TestFXInstalledSmoke$' -v
# ダミーの作業内容で認証済み実モデルへ接続（明示実行時のみ。利用枠を消費する場合あり）
WSUP_FX_LIVE=1 go test ./internal/wsup -run '^TestFXInstalledConnection$' -v
```

テストは一時Gitリポジトリと偽のLLMエンジンを使います。通常のテストでライブモデルやAPI課金は発生しません。実モデルとの認証・応答互換性は別途実環境での検証が必要です。
